# Voxby

Voxby is a synth music tracker for the browser, aimed at writing music small
enough to ship inside a [js13kGames](https://js13kgames.com) entry — the song is
a few hundred bytes of plain JS data, played back by a tiny synth routine at
runtime.

Live at **[ryanbmalm.com/voxby](https://ryanbmalm.com/voxby/)**.

It is a rewritten editor around the audio engine of Marcus Geelnard's
[SoundBox](https://gitlab.com/mbitsnbites/soundbox), whose oscillators, effects
chain and instrument presets it keeps. What is new is the editing side: every
channel's pattern side by side instead of one at a time, an on-screen piano
with scale/chord-aware note entry, genre chord palettes with voice leading,
chord-following melody entry, an oscilloscope, transpose and clipboard
operations, songs exported as `export default {...}` ES modules (and
re-importable), and share links that carry a whole song in the URL.

> **This branch is `synth-v2`, a new direction rather than an upgrade.** The
> song format has changed and is **not** compatible with SoundBox's. Notes are
> gated — a note-off ends a sound rather than a fixed envelope length — and the
> synth gained portamento, vibrato, per-row tempo and per-note instrument
> changes, none of which the old format can express. A SoundBox song still
> *imports*, converted on the way in; nothing exports back out to one. See
> [`plans/voxby-synth-v2.md`](https://github.com/Rybar/js13k2026/blob/main/plans/voxby-synth-v2.md)
> in the parent repo for the design and the reasoning.

## Running locally

Serve the directory over HTTP — `file://` will not work, since the editor is
built from ES modules:

```bash
cd path/to/voxby
python3 -m http.server 8008
```

Then open `http://localhost:8008/`.

Voxby is developed inside [Rybar/js13k2026](https://github.com/Rybar/js13k2026)
as a submodule at `tools/soundbox/`, where it is served by that repo's shared
dev-tool server and covered by its headless-Chrome test suites
(`tests/soundbox/`).

## Layout

| | |
|---|---|
| `main.js`, `panels/`, `state.js`, `menu.js`, `theme.js`, `icons.js` | the editor: entry point, one module per panel (instrument, tracker, keyboard, scope), UI state, generic popup menu, theming, inline SVG icons |
| `engine2.js` | the song data model the editor reads and writes — JS import and export, share links, conversion from a SoundBox song, no DOM |
| `engine.js` | the **SoundBox** data model. Not replaced: it still owns the binary and sonant-x importers, which `engine2.convertV1()` reads through. Nothing writes it any more |
| `scales.js`, `chords.js`, `layouts.js` | scale/chord/voicing math for note entry; genre chord-palette tables; keyboard-layout tables for the piano's key hints |
| `songs/` | song library, each a plain ES module. Still SoundBox songs, converted at load |
| `player-worker.js` | the renderer behind Play and Export WAV. The same algorithm as `src/js/core/voxby.js` in the parent repo, plus a render window so one sequence row can be played on its own — **keep the two in step**, or the editor lies about what a game will play |
| `player.js`, `player-small.js`, `jammer.js`, `presets.js`, `rle.js`, `common.js`, `third_party/` | upstream SoundBox — the worker wrapper, the minimal v1 player, the live-preview jammer, instrument presets, compression |
| `demo.html`, `arpeggio-demo.html` | upstream's standalone examples of using `player-small.js` in your own page |
| `help.html`, `help.css`, `help/` | the manual. Its screenshots are generated by `npm run help-shots` in the parent repo (`scripts/help-shots.mjs`), which drives the editor in headless Chrome — regenerate them after a UI change rather than cropping by hand |

Upstream's own editor (`gui.js`, the `gui/` sprite sheet, `demo-songs.js`,
`logo.svg`) and its help pages are gone: every panel is ported and covered by
tests, and the manual is written for this UI.
